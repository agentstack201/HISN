# حِصن (HISN) — التقرير الفني النهائي

منصة تقييم أمن تطبيقات الويب — مشروع تخرج دبلوم الحوسبة

## 1. الملخص

حِصن تطبيق ويب يساعد صاحب الموقع (أو من لديه تصريح) على فحص موقعه بحثًا عن نقاط الضعف الشائعة وفهم كيفية إصلاحها. يرسل التطبيق من الخادم عددًا قليلًا من طلبات HTTP العادية، ويحلل الاستجابات، ثم يحفظ النتائج مع **الدليل الملاحظ** ودرجة الخطورة وطريقة المعالجة. يستطيع المستخدم متابعة سجل الفحوصات ومقارنتها وتنزيل تقرير PDF.

المشروع ليس أداة اختراق: لا يهاجم ولا يزحف ولا يفحص المنافذ. وعدم العثور على مشكلات **لا يعني أن الموقع آمن تمامًا**.

## 2. الأهداف

1. بناء تطبيق عملي كامل وليس نموذجًا شكليًا.
2. إظهار تطبيق مبادئ أمنية: التحقق من المدخلات، المصادقة والتفويض، عزل بيانات المستخدمين، الحماية من SSRF.
3. أن يكون الكود بسيطًا يمكن لطلاب الدبلوم شرحه والدفاع عنه.
4. أن تكون النتائج حقيقية ومدعومة بأدلة، لا مفبركة.

## 3. التقنيات المستخدمة

| المجال | التقنية | سبب الاختيار |
|---|---|---|
| الواجهة والخادم | Next.js 15 (App Router)، React 19، TypeScript | كود واحد للواجهة والخادم، وServer Actions تبقي المنطق الحساس على الخادم |
| التصميم | Tailwind CSS 4 | سريع وواضح، ويدعم RTL |
| قاعدة البيانات والمصادقة | Supabase (PostgreSQL + Auth + RLS) | لا نبني نظام كلمات مرور بأنفسنا |
| التحقق من المدخلات | Zod | مخططات واضحة تُستخدم في كل النماذج |
| التقارير | pdf-lib | JavaScript خالص دون متصفح خفي |
| الاختبارات | Vitest، Playwright، سكربت SQL لاختبار RLS | |

لم نستخدم خادمًا منفصلًا ولا Docker ولا Redis ولا Python، لأن لا حاجة موثقة لها.

## 4. البنية العامة

```
المتصفح ──HTTPS──▶ Next.js ───────────────▶ Supabase (Auth + PostgreSQL مع RLS)
                     │ صفحات (Server Components)
                     │ app/actions.ts (Server Actions)
                     │ lib/scanner.ts ──طلبات آمنة──▶ الموقع المفحوص
                     └ Service Worker (ملفات ثابتة فقط)
```

| الوحدة | الوظيفة |
|---|---|
| `lib/targets.ts` | التحقق من الرابط، وحماية SSRF، وجلب آمن بتحويلات محدودة |
| `lib/security-checks.ts` | الفحوصات نفسها (دوال نقية بلا شبكة، سهلة الاختبار) |
| `lib/scanner.ts` | تشغيل الفحص وتجميع النتائج، ولا يرمي أخطاء الشبكة |
| `lib/reports.ts` | تحميل الفحص وبناء ملف PDF |
| `lib/validation.ts` | مخططات Zod |
| `lib/finding-text.ts` | الترجمة العربية للنتائج وقت العرض |
| `app/actions.ts` | كل النماذج: دخول، مواقع، فحص، إعدادات |

## 5. قاعدة البيانات

```
auth.users 1──1 profiles
auth.users 1──* targets 1──* scans 1──* findings
```

أربعة جداول فقط: `profiles` و`targets` و`scans` و`findings`، مع مفاتيح أجنبية وقيود CHECK (الخطورة، الحالة، نوع الرابط) وفهارس. حذف موقع يحذف فحوصاته ونتائجه تلقائيًا. مشغّل (trigger) ينشئ ملف المستخدم عند التسجيل.

### سياسات الحماية (RLS)

- كل جدول مغلق ولا يُقرأ منه إلا ما يخص المستخدم.
- **النتائج** (`findings`) لا تحمل `user_id`: تُقرأ فقط إذا كان **الفحص الأب وموقعه** ملكًا للمستخدم، ولا تُضاف إلا لفحصه الجاري.
- لا يمكن إنشاء فحص على موقع شخص آخر ولا نقل فحص إلى موقع غيره.
- لا يُستخدم مفتاح service-role في أي مكان. المتصفح يحمل المفتاح العام فقط.

## 6. خوارزمية الفحص

```
1. اجلب الرابط (حتى 5 تحويلات، كل تحويل يُتحقق منه من جديد)
2. اجلب نسخة http:// لمعرفة هل تُحوَّل إلى HTTPS
3. شغّل الفحوصات على الاستجابات المحفوظة:
   أ) HTTPS: هل يعمل؟ هل الشهادة موثوقة؟ هل قاربت على الانتهاء؟ هل يوجد تحويل؟
   ب) الترويسات: HSTS، CSP، X-Content-Type-Options، Referrer-Policy، Permissions-Policy
   ج) ملفات الارتباط: Secure وHttpOnly وSameSite (تُحفظ الأسماء فقط، لا القيم)
   د) إعدادات خاطئة: كشف الإصدارات، Clickjacking، عرض المجلدات، CORS مع بيانات الاعتماد
4. احفظ النتائج، وسجّل الحالة (completed/failed) والوقت
```

### قواعد دقة النتائج

- أنواع النتيجة: **ناجح، فاشل، معلومة، غير حاسم**.
- خطأ الشبكة أو انتهاء المهلة = **فحص فاشل بلا نتائج**، وليس ثغرة.
- عدم استجابة HTTP = «غير حاسم» وليس ثغرة.
- الترويسة المفقودة تُصنَّف متوسطة أو منخفضة، ولا تُصنَّف حرجة أبدًا (هي تقوية وليست استغلالًا مؤكدًا).
- كل نتيجة لها: عنوان، وصف، دليل فعلي، معالجة، درجة ثقة، وقت الاكتشاف.

## 7. الأمان

### 7.1 الحماية من SSRF (`lib/targets.ts`)

| التحكم | التنفيذ |
|---|---|
| البروتوكول والمنفذ | http/https فقط، المنافذ الافتراضية فقط (لا فحص منافذ) |
| بيانات الاعتماد في الرابط | مرفوضة |
| الأسماء الداخلية | localhost و*.local و*.internal وأسماء بلا نقطة |
| عناوين IP | يجب أن تكون عامة: تُحجب 10/8 و127/8 و169.254/16 (بيانات السحابة) و172.16/12 و192.168/16 وIPv6 الخاصة والمعنونة IPv4 |
| DNS | تُفحص **كل** العناوين الناتجة، وعنوان خاص واحد يرفض الطلب |
| DNS rebinding | دالة `lookup` تفحص ثم تتصل **بنفس العنوان** دون استعلام ثانٍ |
| التحويلات | يدويًا، 5 كحد أقصى، تُفحص كل مرة |
| الحدود | 8 ثوانٍ للطلب، 30 للفحص، 256 كيلوبايت للاستجابة |

### 7.2 الحماية من إساءة الاستخدام (`startScan`)

الفحص المباشر معطّل ما لم يُفعَّل `LIVE_SCANNING_ENABLED=true`؛ تسجيل دخول إلزامي؛ تأكيد ملكية الموقع؛ تحميل الموقع مع فلتر المالك؛ **5 فحوصات لكل مستخدم كل 10 دقائق**؛ فحص جارٍ واحد لكل موقع؛ 3 فحوصات متزامنة كحد أقصى لكل خادم.

### 7.3 المصادقة والتفويض

Supabase Auth يدير كلمات المرور. `requireUser()` يستخدم `getUser()` الذي يتحقق من الرمز لدى Supabase ولا يثق بالكوكي. رسالة خطأ الدخول موحدة (لا يُكشف وجود البريد). التفويض على طبقتين: فلتر `user_id` في الكود + RLS في قاعدة البيانات.

### 7.4 أمان التطبيق نفسه

ترويسات: CSP (`frame-ancestors 'none'`)، HSTS، nosniff، Referrer-Policy، Permissions-Policy، X-Frame-Options، وإزالة `X-Powered-By`. تقارير PDF تُرسل بـ `Cache-Control: private, no-store`. الـ Service Worker يخزّن الملفات الثابتة العامة فقط، ولا يخزّن الصفحات ولا النتائج.

## 8. الواجهة وتجربة الاستخدام

- الصفحة الرئيسية بفيديو القلعة (بلا صوت، يتوقف عند طلب تقليل الحركة، مع زر إيقاف).
- العربية افتراضية بتخطيط RTL، مع الإنجليزية LTR. النتائج تُترجم وقت العرض، والدليل يبقى كما رُصد.
- صوت نقر اختياري بزر تشغيل/إيقاف يتذكره الجهاز.
- تطبيق قابل للتثبيت (PWA) مع صفحة عدم اتصال وتنبيه تحديث.
- لوحة التحكم تعرض أرقامًا من قاعدة البيانات فقط، والمعاينة في الصفحة الرئيسية موسومة صراحةً ببيانات توضيحية.

## 10. القيود المعروفة

1. فحص رابط واحد بطلبات GET فقط؛ لا يختبر منطق التطبيق ولا الحقن ولا الصفحات خلف تسجيل الدخول.
2. المنافذ الافتراضية فقط (80 و443).
3. تقرير PDF بالإنجليزية فقط (خطوط pdf-lib القياسية لا تدعم العربية).
4. حد التزامن محفوظ في ذاكرة الخادم (لكل نسخة)، أما حد المعدل فمن قاعدة البيانات.
5. سياسة CSP تسمح بسكربتات inline لأن Next.js تحتاجها.
6. الفحص قد يمر عبر وكيل (proxy) في بعض الاستضافات، وهذا يتجاوز فحص IP، لذلك يجب التحقق قبل التفعيل العام.

## 11. أعمال مستقبلية

نشر على استضافة وتفعيل الفحص العام بعد التحقق من بيئتها؛ تقرير PDF بالعربية (يحتاج خطًا عربيًا وتشكيل الحروف)؛ سياسة CSP بـ nonce؛ فحوصات إضافية (TLS المتقدم، ملفات حساسة معروفة بحذر)؛ فحص مجدول وتنبيهات؛ اختبارات وصول آلية.

## 12. الخلاصة

تحقق الهدف: تطبيق يعمل فعليًا على قاعدة بيانات حقيقية، وفحص حقيقي مدعوم بالأدلة، وحماية متعددة الطبقات (SSRF، RLS، حدود المعدل)، واختبارات آلية أُجريت وسُجلت نتائجها. القرارات التقنية موثقة في `decisions.md`، والتهديدات في `threat-model.md`، وخطة العرض وأسئلة المناقشة في `demo-and-viva.md`.
